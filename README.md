# 코토바 · JLPT N3 한자·어휘 학습

React + TypeScript + Vite + Tailwind CSS + Dexie(IndexedDB) + PWA로 구현한 개인 학습 MVP입니다. 서버·계정 없이 브라우저에 학습 데이터를 저장합니다. 밝은 정원 테마, 모바일 하단 내비게이션, 44px 이상 버튼, 한국어 설명과 일본어 단어 표시를 제공합니다.

## 실행

Node.js 24 권장(이 환경: 24.19.0), npm 11.

```bash
cd /workspace/japanese-study
npm ci --cache /workspace/.npm-cache
npm run dev
```

개발 서버 기본 포트는 5173이며 모든 네트워크 인터페이스에 바인딩합니다. 클라우드 환경에서는 플랫폼이 제공하는 접속 기능을 사용하세요. 학습 데이터는 **접속한 origin 및 브라우저별**로 저장되므로 개발 서버와 배포 앱의 기록은 별개입니다.

프로덕션/PWA 확인:

```bash
npm run build
npm run preview -- --port 4173
```

PWA 서비스 워커는 프로덕션 빌드에서 동작합니다. 정상적인 온라인 첫 실행이 필요하며 이후 캐시된 앱과 IndexedDB로 오프라인 학습할 수 있습니다. 외부 폰트나 런타임 API에 의존하지 않습니다. 최초 seed 등록은 DB 생성 시에만 실행됩니다.

## 구현 기능

- 홈: 오늘 풀이 수·정답률·복습 단어 수, 최근 7일 학습 발자국, 학습 단어 수
- 단어장: 검색, 단어의 읽기·의미, 개별 구성 한자를 누르면 상세 카드
- 한자 카드: 한국 훈·음, 음독·훈독, 뜻, 관련 단어. 누락된 값은 ‘미등록’ 표시
- 읽기/의미/혼합 퀴즈: 단어 단위 4지선다, 선택 후 정답 확인, 정오답 피드백, 단어 상세, 즐겨찾기
- 정답 확인 시 풀이와 누적 통계를 하나의 트랜잭션으로 저장. 중복 클릭 방지와 저장 실패 안내
- 세션 결과: 문제 수·정답·오답·정답률, 틀린 단어와 다시 풀기
- 오답노트: 단어별 한 항목, 누적 오답 횟수와 최근 오답 날짜, 오답만 퀴즈
- 단어·한자 즐겨찾기 저장/해제, 즐겨찾기 **단어**만 퀴즈
- JSON/CSV 가져오기, 형식 검증, 안정적인 단어 ID로 병합, 기존 기록·즐겨찾기 보존
- 전체 백업(한자·단어·풀이 기록·통계·즐겨찾기), 단어 데이터만 내보내기, 확인 후 전체 백업 복원
- 설치 가능한 PWA, 앱 리소스 캐시 및 오프라인 학습

기본 예시 6단어에 사용자가 첨부한 해커스 2–4쪽 144단어를 자동 병합합니다. JLPT N3 공식 전체 목록을 포함하지 않습니다. 개별 한자 훈·음, 음독·훈독 및 뜻은 확인되지 않은 상태로 유지하며 임의로 채우지 않습니다.

기본 세션은 **최대 10문제**입니다. 퀴즈 대상 단어 수가 적으면 줄어듭니다. 오답 선택지는 전체 단어장의 실제 등록된 읽기/뜻에서 가져옵니다. 서로 다른 유효한 답 4개가 없거나 등록된 뜻이 겹치면 해당 문항을 제외합니다. 답을 확인한 기록은 즉시 저장하며 진행 중 세션의 화면 상태는 새로고침 시 재개하지 않습니다.

## 단어 추가

앱의 **데이터 관리**에서 JSON 또는 CSV를 붙여넣거나 파일을 선택하고 ‘검증하고 가져오기’를 누르세요. 채팅으로 제공한 새 단어는 아래 형식의 파일로 정리해 가져올 수 있습니다. 앱이 채팅을 직접 읽지는 않습니다.

JSON 단어 배열:

```json
[
  { "word": "変更", "reading": "へんこう", "meanings_ko": ["변경"] },
  { "word": "断る", "reading": "ことわる", "meanings_ko": ["거절하다"] }
]
```

한자 상세를 함께 보완하는 객체 형식:

```json
{
  "kanji": [
    {
      "character": "変",
      "korean_hun": "",
      "korean_eum": "",
      "onyomi": [],
      "kunyomi": [],
      "meanings_ko": []
    }
  ],
  "vocabulary": [
    { "word": "変更", "reading": "へんこう", "meanings_ko": ["변경"] }
  ]
}
```

위의 빈 한자 값은 형식 안내이며 독음을 추측한 데이터가 아닙니다. 사용자가 확인한 정보를 채워 추가하세요. ID는 정규화한 단어(`v:変更`)와 글자(`k:変`)로 결정됩니다. 같은 단어를 다시 가져오면 읽기와 뜻을 갱신하면서 기록을 유지합니다. 기존 한자의 상세 필드는 빈 입력으로 지우지 않습니다. JSON 내 중복 단어는 오류를 안내하며, 이미 DB에 있는 동일 단어는 병합합니다. 단어에 포함된 한자 연결은 자동으로 설정됩니다. 선택 필드 `jlpt_level`, `source`를 지원합니다.

CSV:

```csv
word,reading,meanings_ko
変更,へんこう,변경
断る,ことわる,거절하다
```

여러 뜻은 `|`로 구분합니다. 쉼표·줄바꿈을 포함한 셀은 CSV 따옴표로 감싸세요. 파일 가져오기는 최대 5MB입니다.

전체 백업은 JSON입니다. ‘전체 백업 다운로드’로 저장한 파일을 가져오면 항목 수를 확인한 뒤 복원할 수 있습니다. **복원은 현재 데이터와 기록을 백업 내용으로 교체**합니다. 일반 단어 가져오기는 병합하며 기록을 삭제하지 않습니다. 백업은 연결 ID·기록·통계의 일관성을 검증한 후 하나의 트랜잭션으로 복원합니다. 브라우저 데이터 삭제 또는 기기 변경 전에 백업하세요. 기기간 자동 동기화는 제공하지 않습니다.

## 모바일·설치

- 동일 LAN에서 개발하려면 서버가 실행되는 컴퓨터의 LAN 주소와 5173 포트로 접속할 수 있습니다(기본 바인딩 적용). HTTP LAN 접속은 UI 개발 확인용입니다.
- 실제 PWA 설치/오프라인 기능은 HTTPS로 `dist/`를 정적 호스팅한 앱에서 사용하세요. localhost도 개발용 보안 컨텍스트로 지원됩니다.
- iPhone: Safari에서 앱을 열고 공유 → **홈 화면에 추가**. Android/데스크톱: 지원 브라우저의 설치 메뉴.
- Chromium의 iPhone 13 화면 크기로 자동 검증했습니다. 실제 iPhone Safari 및 홈 화면 설치는 실기기에서 별도 확인해야 합니다.

## 해커스 2–4쪽 데이터 등록

사용자가 제공한 `jlpt_n3_hackers_pages_2-4.json` 원본을 `src/data/hackers-pages-2-4.json`에 보관하고 앱 시작 시 한 번 자동 병합합니다. 원본 한자 ID를 해석해 기존 안정적인 DB ID로 연결하며 원본 ID는 `source_id`로 보존합니다. DB 버전 2에서 등록 결과만 기록하는 `metadata` 테이블을 추가합니다. 기존 `history`와 `progress` 테이블은 수정하지 않습니다.

기본 6단어 DB 기준: 신규 단어 **144개**, 신규 한자 **216개**, 중복 한자 병합 **5개**, 오류 **0개**. 최종 단어 150개, 한자 227개입니다. 이미 사용자가 가져온 데이터가 있다면 실제 추가 수는 달라집니다. 앱의 데이터 관리 화면에서 해당 기기의 등록 결과를 확인할 수 있습니다.

- 교재 별표 64개는 `Vocabulary.starred_in_book`으로 저장합니다. 사용자 즐겨찾기(`StudyProgress.is_favorite`)를 변경하지 않습니다.
- `null`인 한국 훈·음, 음독·훈독, 한자 의미는 `null`로 유지합니다. 기존에 보완한 값은 누락된 입력으로 지우지 않습니다.
- 이후 검증된 사전 정보는 `{ "kanji": [...] }` JSON만으로도 보완할 수 있습니다. `metadata_source`, `metadata_status`를 보관하며 단어·기록을 삭제하지 않습니다.
- 수동 JSON 재가져오기는 병합하며 중복 단어/한자 추가를 방지합니다. 최초 자동 등록은 데이터셋 ID와 버전으로 표시해 재실행 시 기존 정보가 덮어써지지 않습니다.
- 전체 백업에는 교재 별표와 null 한자 상세도 포함됩니다. 명시적 백업 복원으로 교체한 데이터는 다음 실행 때 자동으로 다시 채우지 않습니다.
- 신규 단어는 같은 단어장·읽기/의미/혼합 퀴즈에서 바로 사용합니다. 기존 최대 10문제 세션 규칙을 적용합니다.

현재 검증은 단위 테스트 16개(실제 첨부 데이터·재병합·null 보존·사전 보완·v1 업그레이드 포함) 및 브라우저 테스트 4개입니다.
